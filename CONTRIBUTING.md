# Contributing

All work begins with a GitHub issue created from the repository work-item template.

## Definition of ready

An issue is ready only when it has:

- A specific objective
- Scope and exclusions
- Named deliverables
- Required context
- Dependencies
- Source requirements
- Acceptance criteria
- Validation instructions
- A target milestone

## Definition of done

Work is done only when:

- All acceptance criteria are satisfied.
- Required validation passes.
- Terminology is consistent with the glossary.
- New normative requirements have stable identifiers.
- Applicable sources and decisions are recorded.
- Internal links resolve.
- Traceability is updated where required.
- The pull request contains no unrelated changes.

## Pull requests

Pull requests should normally resolve one issue. Keep changes bounded and reviewable. A pull request must explain what changed, why it changed, how it was validated and what remains unresolved.

Substantive guidance should not be added until the repository foundation is approved.
