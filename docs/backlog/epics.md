# Epic Catalog

The catalog defines the complete planned product. GitHub issues created after foundation approval will provide bounded implementation work packets.

## EPIC-00: Repository and methodology governance

Establish schemas, terminology, source controls, decisions, validation, traceability, contribution rules and publication governance.

## EPIC-01: Normative core

Define accountability, bounded authority, evidence, risk, control precedence, reversibility, context ownership, exception handling and system improvement.

## EPIC-02: Adoption system

Define Foundation, Assisted Work, Bounded Change, Governed Workflow and Selective Orchestration, including entry, continuation, restriction and exit conditions.

## EPIC-03: Readiness system

Define organizational, engineering, context, control, measurement and team readiness, including decision and remediation procedures.

## EPIC-04: Enterprise foundation

Define ownership, AI stance, approved-use categories, risk classes, minimum controls, baseline measures, pilot selection, support and incident channels.

## EPIC-05: Assisted-work procedures

Define safe advisory workflows for analysis, explanation, drafting, test suggestions, review assistance and incident summarization.

## EPIC-06: Bounded-change procedures

Define classification, preparation, planning, constrained execution, deterministic verification, human review, evidence and controlled release.

## EPIC-07: Governed workflows

Define intent, clarification, specification, planning, decomposition, execution, verification, integration, release evidence and production learning.

## EPIC-08: Selective orchestration

Define eligibility, delegation, coordination, authority, tool use, evidence transfer, observation, stop behavior and revocation.

## EPIC-09: Control system

Define identity, authorization, isolation, context, tools, deterministic checks, inferential review, human approval, audit, evidence, incidents and revocation.

## EPIC-10: Artifact system

Define the enterprise charter, use-case intake, readiness decision, pilot charter, risk record, specification, plan, approval, verification, release, feedback and advancement artifacts.

## EPIC-11: Roles and operating model

Define enterprise, value-stream, team, platform, product, architecture, security, delivery and operations accountability.

## EPIC-12: Measurement and decisions

Define baselines and balanced measures for flow, quality, operations, security, governance, product, developer experience and economics.

## EPIC-13: Pilot and adoption

Define use-case selection, pilot design, training, support, observation, review, advancement, restriction and repeatable adoption cycles.

## EPIC-14: Worked examples

Validate the playbook against advisory, testing, defect, dependency, feature, schema, authentication, modernization, incident and regulated-change scenarios.

## EPIC-15: Facilitation

Define leadership alignment, readiness, pilot design, team onboarding, pilot review, advancement and periodic control-review sessions.

## EPIC-16: Enterprise operation

Define mixed-state governance, exceptions, reassessment, cost, context ownership, control lifecycle and organization-wide enablement.

## EPIC-17: Publication

Publish canonical Markdown as accessible responsive documentation and generate controlled distribution formats after content stabilization.

## Backlog creation rule

An epic must be decomposed into issues with objective, scope, exclusions, dependencies, required context, source requirements, deliverables, acceptance criteria, validation and target milestone. Issue creation begins only after the foundation pull request is approved.
