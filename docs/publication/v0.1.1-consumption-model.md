# Version 0.1.1 Consumption Model

## What changed

Version 0.1.1 adds a human-centered consumption layer to the Pilot Edition. It does not replace or weaken the version 0.1 method.

End users now enter through a 22-page [Pilot Guide](../guide/README.md) organized around five tasks:

1. Understand
2. Prepare
3. Run
4. Decide
5. Reference

The guide makes the purpose, audience, participants, first action, operating sequence, stop conditions and decisions visible without requiring readers to understand the repository structure.

## One working surface

The [Pilot Workbook](../guide/reference/pilot-workbook.md) consolidates the records a pilot team actively completes. It has a defined completion order and covers ownership, use-case selection, readiness, boundaries, baseline, charter, onboarding, weekly observations, risks, evidence review, the final decision and the next increment.

Canonical artifact definitions and templates remain authoritative. The workbook links to them where deeper evidence is required.

## Progressive disclosure

The primary guide uses plain-language summaries and point-of-need links. Detailed procedures, controls, role definitions, measures, identifiers, decisions, source provenance and traceability remain in the canonical playbook.

This keeps the primary path approachable while preserving the rigor needed by implementers, risk owners and assurance reviewers.

## What did not change

- Assisted Work remains the default starting mode.
- Bounded Change still requires every canonical lifecycle gate.
- Humans remain accountable for consequential decisions.
- Existing engineering, security, review and release controls remain authoritative.
- Quality, control integrity, recoverability and participant safety can block expansion.
- Approval for one scope does not transfer to another team, repository, use case, data class or authority level.
- Platform-specific implementation guidance remains outside the vendor-neutral core.

## Validation

The repository now checks that the primary guide contains exactly 22 pages, includes all five navigation sections, preserves the action-page contract, contains no Markdown tables or em dashes and does not expose internal identifiers.

The existing content validation continues to check repository structure, terminology and relative links.

## Known limitation

The guide has been checked through structured sponsor, pilot-lead and delivery-team walkthroughs against the approved acceptance criteria. It has not yet been tested with independent enterprise users in a live pilot. That validation should be captured during the first external adoption and used to reduce friction further.
