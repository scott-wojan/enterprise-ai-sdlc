# Anchor 3 Selection and Responsive Review

## Status

Desktop structure selected for responsive validation. Mobile structure pending product-owner review.

This is not approval of the complete Gate 6.4 anchor set, visual system, prototype or production interface.

## Represented moment

This review covers one moment only:

- the first controlled pilot is proposed and has not launched;
- the initiative is assessing readiness;
- the stop-path response has just been interpreted;
- the current response created the third active blocker;
- two blockers existed before the current response;
- current AI participation remains Foundation;
- the user must understand the consequence and create remediation.

## Product-owner selection

On 11 August 2026, the product owner selected the second desktop exploration as the better option for representing this one moment.

The selection approves the cause-to-effect structural direction for responsive validation. It does not approve final styling or authorize extension to other screens without validation.

## Selected desktop artifact

[Anchor 3 desktop selected](explorations/anchor-3-desktop-selected.png)

The desktop direction uses this sequence:

1. restrained initiative and journey context;
2. the interpreted response;
3. the result caused by that response;
4. prior blockers and the remaining aggregate state;
5. what may continue;
6. what must stop;
7. the recommended next action;
8. links to the complete readiness view and source response.

## Preliminary principle review

### UXP-001: Start with the human and the job

Pass for structural review. The screen serves a pilot lead who must understand an interpreted result and begin safe remediation.

### UXP-002: Keep meaning and behavior consistent

Pending cross-view validation. Desktop and mobile use the same terms and sequence, but the pattern has not yet been tested against the connected work-item and gate screens.

### UXP-003: Design for scanning

Pass for visual inspection. Response, result, permitted work, prohibited work and next action use direct headings.

### UXP-004: Remove unnecessary interpretation and choice

Pass for structural review. The screen states what caused the blocker, what existed before it, what resolving it changes and what the user should do next.

### UXP-005: Use visual structure to communicate relationships

Pass for structural review. The chronological sequence connects response, consequence and recovery without a detached result rail.

### UXP-006: Define the problem before the solution

Pass. The governing anchor brief records user, state, screen responsibility and validation questions.

### UXP-007: Use direct language without jargon

Pass for visual inspection. Material terms are used in direct sentences. Representative-human comprehension remains required.

### UXP-008: Give immediate and meaningful feedback

Pass for the represented state. The result explains what changed, what did not change and what happens next.

### UXP-009: Match hierarchy to user priority

Pass for structural review. The interpreted response and result govern the page. Journey context remains restrained.

### UXP-010: Treat accessibility as a design requirement

Pending annotation and interactive validation. Semantic order is defined, but keyboard, focus, announcement, contrast, zoom and reflow evidence are not complete.

### UXP-011: Preserve user control and reversibility

Pass for structural review. The user can review the source response, return to readiness work and create remediation without automatically changing authority.

### UXP-012: Use whitespace to reduce cognitive load

Pass for visual inspection. The composition uses spacing and dividers instead of dashboard cards.

### UXP-013: Prevent errors and make recovery explicit

Pass for structural review. The next action, owner and effect of verification are explicit.

### UXP-014: Reveal complexity when relevant

Pass for structural review. The screen states the two prior blockers without reproducing the complete readiness overview.

### UXP-015: Use familiar mental models

Pending representative-human validation. The page uses a familiar result and recovery sequence but has not been tested with target users.

### UXP-016: Iterate from observed evidence

In progress. The first exploration was rejected, the second direction was selected and mobile review is next. Representative task validation and retest remain required.

## Current blocking conditions

Anchor 3 cannot be approved until:

- the mobile adaptation is reviewed;
- desktop and mobile accessibility annotations are complete;
- a representative reviewer can answer the twelve validation questions in the anchor brief without designer explanation;
- any resulting failures are corrected and retested.

## Exact review question

Does the mobile adaptation preserve the selected desktop meaning and hierarchy without making the state, cause, remaining blockers, permitted work, prohibited work or recommended next action harder to understand?
