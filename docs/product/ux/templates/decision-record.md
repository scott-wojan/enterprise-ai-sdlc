# DEC-UX-###: Decision Title

## Status

Proposed

Use one status: Proposed, Accepted, Rejected or Superseded.

## Decision date

YYYY-MM-DD

## Decider

Name the accountable role or product owner. Do not imply that an AI system approved the decision.

## Scope

State the product surface, journey stage, screen, component, interaction or Gate affected.

## Context

Describe the user problem, evidence, constraints and prior decisions that make this decision necessary.

## Decision

State exactly what is being decided.

Separate mandatory requirements from recommendations.

## Reasons

Explain why this option was selected.

## Alternatives considered

For each material alternative, record:

- description;
- benefit;
- cost or risk;
- reason selected or rejected.

## Consequences

Record:

- work enabled;
- work still blocked;
- affected content or behavior;
- responsive consequences;
- accessibility consequences;
- implementation consequences;
- validation required.

## Affected sources

Link every governing document, wireframe, prototype, issue and pull request that must be updated.

## Validation required

State the task, participant, viewport, device, accessibility or comparison evidence needed to confirm the decision works.

## Supersedes

Name any earlier decision replaced by this record.

Use "None" when the record does not supersede another decision.

## Superseded by

Link a later accepted record when this decision is replaced.

Use "None" while current.

## Unresolved questions

List only questions that do not prevent this decision. Material unresolved product questions keep the record Proposed.
