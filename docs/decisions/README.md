# Methodology Decision Register

This register preserves consequential decisions so later work does not depend on conversation memory.

## DEC-001: GitHub is the project source of truth

**Status:** Accepted.

Project scope, decisions, sources, content, backlog and progress are maintained in this repository.

## DEC-002: Markdown is the canonical authoring format

**Status:** Accepted.

Responsive HTML, PDF, Word and other formats will be generated from canonical content after the structure stabilizes.

## DEC-003: The core playbook is platform-neutral

**Status:** Accepted.

Product-specific implementation details may later be created as adapters. They must not be embedded in the normative core.

## DEC-004: The complete product is architected before incremental implementation

**Status:** Accepted.

The roadmap and backlog represent the full intended product from the start. Milestones constrain implementation, not product vision.

## DEC-005: Adoption states are not a linear maturity contest

**Status:** Accepted.

Organizations may remain at any state appropriate to a team, repository or work type. Greater autonomy is not inherently better.

## DEC-006: Version 0.1 is a Pilot Edition

**Status:** Proposed for foundation review.

The first content release will implement enough foundation, assisted-work and bounded-change guidance to conduct controlled pilots. Later states will remain represented but not yet normative for adoption.

## Decision process

New decisions must record:

- Status
- Context
- Decision
- Alternatives considered
- Rationale and evidence
- Consequences
- Affected content
- Conditions for reconsideration

Decisions that need substantial analysis should use a separate file named with the next `DEC` identifier.
